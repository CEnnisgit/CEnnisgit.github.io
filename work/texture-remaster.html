Case study · 2026 · part of the 358 Days Remake

Upscaling DS textures with image models, and checking the results with numbers

Ask an image model to modernize a texture and it will often change the design too. So I measure every output against numeric targets and the original layout, and throw out the ones that drift.

RoleCame up with the method, directed the tooling
TimelineSep 2026
StackPython, OpenCV, NumPy, SciPy
OutputKept local, never committed

What was hard

The DS textures are tiny and use few colors. I want them to look like a modern Unreal game. Telling a model "make it look like KH3" gives you random palettes and made-up detail. I needed results I could repeat that kept the original layout.

What I did

  • Learn from real pairs. I took old and new textures of the same location from the actual games and measured what changed: saturation down 33 to 50%, hue the same, brightness mostly the same, fine detail up 20 to 45%. One pair was a redesign, so I dropped it. A redesign isn't a rule.
  • Different paths per texture. Image-model generation, reusing an existing HD version, or procedural work (vector upscale, gradient, alpha, redrawn linework, and a strict mode that adds nothing new).
  • One folder per job. Each has the upscaled layout, a k-means map of tone regions, in-game lighting, references, a prompt with numeric targets, and pass thresholds.
  • Automatic checks. Edges have to line up with the original within 3 px, and mean RGB, saturation, brightness and detail have to hit their targets. Then the palette gets locked, the image gets aligned onto the original layout, and it goes in a READY log.
  • Previews that match the engine. I ported the old UE 4.18 tonemapper (a baked 32³ LUT) so previews look like they will in-game.

Numbers

In this test the model never saw the real modern texture. It only got feedback as numbers and short notes.

AttemptSaturationBrightnessMean RGBFine detail
KH2 input0.600.45(177, 99, 72)0.020
v1: pairs + rules only0.600.44(170, 99, 69)0.021
v2: + corrections0.490.53(180, 124, 93)0.028
v3: + numeric targets0.380.50(160, 121, 99)0.031
KH3 real (hidden)0.370.46(147, 111, 92)0.024

By v3 the saturation was 0.01 off the hidden texture. It still wasn't a match: the real one has thinner grout, more marbled stone and more variation between slabs.

My role

The learn-from-pairs idea and the rules were mine. AI agents wrote and ran most of the tooling (about 30 Python modules) following those rules. I decided what passed.

IP note

The textures belong to Square Enix / Disney. Generated images stay on my machine. They're never committed, published or shown here. This page only covers the method and my measurements.
