Case study · 2026 · non-commercial fan project

358 Days Remake in Unreal C++

I'm remaking a 2009 Nintendo DS action RPG in Unreal Engine 5.8. Making it look modern is the easy part. Proving it plays like the original is hard, so most of the work is a test harness.

RoleProject lead and architect
TimelineSep 2026 – ongoing
StackUE 5.8 C++, Python, Lua
StatusSystems in progress; not yet playable end to end

What was hard

A remake that only looks right is easy to demo and hard to debug. Missions, panels, rewards, enemies and saves all affect each other. Change one and the difficulty shifts somewhere else. I didn't want to claim anything matched the original unless I'd measured it.

What I did

  • The original game is the spec. I run it in an emulator from a known state with recorded inputs, record what happens frame by frame, and turn that into checks with tolerances.
  • Game rules live outside Unreal. The rules core (DaysDomain) is deterministic and doesn't know about the engine. Unreal C++ adapters sit around it. The UI can only read state, and only the save layer writes saves, so an animation callback can't hand out a reward twice.
  • More than pass/fail. Results are PASS, FAIL, INVALID, INCOMPARABLE or SYNTHETIC_PASS. Each report fingerprints its inputs and points at the first line where the traces differ.
  • Safe test runs. Checks before a run starts, a watchdog, locked logs, and cleanup that confirms saves and config files weren't touched.
  • Content is data. Missions, spawns and rewards are data files. A hash of the mission data has to match after every refactor.

My role

To be straight about it: AI coding agents (Codex, Claude) wrote much of the code. I wrote the specs and rules they worked from, decided what counted as matching the original, and set the checks code had to pass. I split up the work, reviewed it, and threw out claims the tests didn't support. One other person wrote a separate refactor branch.

Numbers

  • 530 commits on the current branch, Sep 6 to Oct 16, 2026.
  • 228 / 228 offline tests passed in one regression run on Sep 27, 2026. Nothing skipped, and the source matched what was tested.
  • 26 / 26 checks passed against the original game's title screen flow. That's 4 scenarios run twice each, including checks that inputs and save RAM weren't altered.
  • I captured the new front end in Unreal at 2560×1440 with no scripted input. It failed the visual check because labels were missing. That's the next task.
  • The refactor has 11 checks it must pass: tests, golden output, spec, guard, coverage, frame-by-frame replay and smoke.

Limits

You can't play it yet. Individual systems and short test runs work. A full mission doesn't yet. It's a non-commercial fan project. Kingdom Hearts is © Square Enix / Disney. The repo has no game assets, ROMs or saves, a pre-push hook blocks them, and nothing is distributed. I left game screenshots off this page on purpose.

Stack

  • C++
  • Unreal Engine 5.8
  • Python (uv workspace)
  • Lua
